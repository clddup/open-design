# OpenPencil 能力对照与复用边界

> 本文是持续更新的竞品/开源实现基准，不是依赖声明，也不代表 OpenDesign 已具备表中能力。当前快照固定为 OpenPencil commit [`449f31dd8b7df12965f65d9da774597332fc153d`](https://github.com/ZSeven-W/openpencil/tree/449f31dd8b7df12965f65d9da774597332fc153d)（2026-08-10）。存在源码或 README 声明只证明值得调查，不能替代 OpenDesign 的产品可达性、像素、双平台和保真验收。

## 结论

OpenPencil 应作为 OpenDesign 的持续产品行为和能力矩阵基准，但不能整包变成第二个内核。

可以直接采用的是经过源码确认的交互原则、工作流拆分、状态机要求和测试场景；可以选择性移植的是与文档状态无关、输入输出纯净且许可证清晰的算法。完整 Rust/Jian/CanvasKit renderer、`.op` 文档模型、Agent runtime、CLI/MCP 任意路径入口和应用 UI 壳不直接接入。OpenDesign 继续由自己的 `DesignDocument`、唯一 `EditorRuntime`、Main capability、Leafer adapter 与专业 service 承载这些能力。

## 客户端技术栈与包体

OpenPencil v0.8.3 不是 Tauri 或 Wails。固定源码中的 `op-host-desktop` 明确描述为 `winit + skia-safe` 原生二进制，实际窗口层使用项目的 `casement`（winit fork），编辑器 UI/文档相关能力来自 Jian，原生绘制依赖 `skia-safe` 的 GL/textlayout/PDF；Web host 才使用 CanvasKit/WASM。README 也明确声明桌面版不携带浏览器引擎。

其 release profile 开启 symbol strip、Thin LTO 与单 codegen unit，源码注释记录未优化时桌面 binary 约 70 MB。v0.8.3 的公开发行资产中，Windows setup 约 36.1 MB（arm64）/39.4 MB（x64），macOS DMG 约 52.0 MB（arm64）/55.9 MB（x64），Linux AppImage 约 48.8–50.5 MB。它比典型 Electron 安装包小的主要原因是没有捆绑 Chromium/Node runtime，并配合 Rust release 链接优化；代价是跨平台 UI、文字、输入法、可访问性、文件对话框和 GPU 后端都由原生栈自行维护。

证据：[`Cargo.toml` release profile](https://github.com/ZSeven-W/openpencil/blob/449f31dd8b7df12965f65d9da774597332fc153d/Cargo.toml)、[`op-host-desktop/Cargo.toml`](https://github.com/ZSeven-W/openpencil/blob/449f31dd8b7df12965f65d9da774597332fc153d/crates/op-host-desktop/Cargo.toml)、[v0.8.3 release assets](https://github.com/ZSeven-W/openpencil/releases/tag/v0.8.3)。

## 复用等级

| 等级          | 处理方式                                         | 要求                                                                            |
| ------------- | ------------------------------------------------ | ------------------------------------------------------------------------------- |
| A：行为基准   | 直接转成 OpenDesign 产品需求、交互测试和验收样张 | 固定上游 commit；记录可观察行为；不复制私有对象                                 |
| B：纯算法移植 | 选择性移植几何、crop、path 或序列化算法          | 证明输入输出纯净；保留来源与许可证；用 OpenDesign 类型重写边界；增加对照 corpus |
| C：窄 adapter | 对成熟独立库或数据格式建立可替换 adapter         | 固定版本、许可证、包体/平台基准、失败语义、第三方通知和 ADR                     |
| D：不接入     | 只保留调研结论                                   | 会建立第二文档/renderer/Agent/权限事实状态，或无法隔离依赖与授权边界            |

## 进入 OpenDesign 计划的规则

每项借鉴必须按以下顺序落地，不能因为上游已经有代码就跳过设计：

```text
固定上游提交与源码证据
→ 写出用户工作流和失败/取消/恢复状态
→ 对照 Figma/其他专业平台确认通用语义
→ 决定 OpenDesign schema/service/adapter 边界
→ ADR 与 capability 状态
→ schema/migration/Runtime/human/Agent/render/export
→ 保存重开/undo/redo/安全/像素/双平台证据
```

如果上游实现与 OpenDesign 当前运行证据冲突，以 OpenDesign 实际运行和已接受边界为准；如果上游只是 README 宣传而没有可达源码或测试，该项只记为待验证，不进入“已支持”。

## 当前优先顺序

1. [已完成] 在 `DesignDocument 1.8.0` network 上实现已有单轮廓节点的 vertex/handle selection 与 drag、point mode、Delete/Backspace、Enter/双击进入和 Escape/Done 退出，并保持 pointer-up 单事务。
2. 继续对照 Figma Vector Networks 与 OpenPencil path-edit，在已完成 Open/Close/Reverse、点击 Cut、开放/闭合 contour、多 Vector edit collection 和跨层有限线 Cut 的基础上，补齐 compound hole/闭合凹形多交点 Cut、connect/disconnect、branch/connected network、套索、多点变换框、flatten、outline stroke 和 Slice。
3. 扩展 SVG 路径/文字/图片/圆角 outline 的保真 corpus，并建立 PNG/JPEG/WEBP/PDF 静态导出 service，不降低现有安全边界。
4. 对照 OpenPencil image crop、font、layout、components 与模板样张，按 Image → Text → Layout → Design System 的依赖顺序推进。
5. Agent 团队、代码生成、协作、Web SDK 和 Tauri/原生壳评估保持后续能力，不用来掩盖当前专业画布缺口。
