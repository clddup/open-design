# ADR-0003：以 DesignEngineAdapter 隔离设计引擎

- 状态：部分被 ADR-0005、ADR-0009 取代
- 日期：2026-08-07
- 保留：版本化 Design Contracts、capability、事务、查询、导入导出和互操作边界
- 取代：把 Renderer 的活动文档、直接操作与低层渲染统一包装为一个外部 DesignEngineAdapter 的范围

## 背景

OpenDesign 需要让 Renderer、Agent、MCP、持久化和格式适配共享稳定的设计行为，同时避免具体渲染库、平台对象或第三方编辑器成为公共协议。

如果 Renderer、Agent、MCP 和持久化直接依赖引擎私有 API，升级会扩散到整个产品，Agent 生成的命令也无法稳定验证。另一方面，试图在第一天抽象所有未来引擎会产生过度设计并丢失实际能力。

## 决策

所有跨进程、Agent、MCP、导入导出和持久化设计访问通过版本化的 OpenDesign 契约进行。ADR-0005 进一步确定 OpenDesign 自己拥有文档与 `EditorRuntime`；ADR-0009 将 Renderer 的场景与直接操作收敛为专用 Leafer adapter。当前 `DesignEngineAdapter` 是互操作与未来 host/service 的能力接口，不是 Renderer 内每次直接编辑必须经过的远程式门面，低层渲染后端也不是另一个文档引擎。

适配器契约围绕可观察行为定义，而不是照搬引擎类：

- `capabilities()` 返回支持的节点、操作、格式、限制和可选特性。
- 文档生命周期覆盖创建、打开、保存、恢复、导入、导出和关闭。
- 查询接口返回通用、可序列化的文档摘要、节点、选区、资源和诊断。
- 写操作采用 `DesignTransaction`，包含稳定 ID、基准文档版本、命令列表和作用域。
- `preview` 在不提交的情况下返回归一化差异、警告和估算影响。
- `apply` 原子提交事务，并返回新版本、变更集和撤销句柄。
- 事件接口归一化文档、选区、历史、视口、资源和故障状态。

公共契约采用明确的 schema 版本。新增可选能力可以向后兼容演进；破坏性变更需要新主版本、迁移说明和同时支持期。调用方必须处理 `unsupported`、`conflict`、`invalid`、`permission-denied`、`cancelled` 和 `engine-failure` 等结构化结果。

## 事务原则

命令描述设计意图，例如创建通用节点、设置属性、应用布局或替换资源，不包含引擎内存地址和私有对象引用。每个命令都有运行时 schema，路径和资源引用受文档作用域限制。

适配器在应用前检查文档版本。版本冲突不能静默覆盖；调用方应重新读取上下文、重放安全命令或请求用户处理。批量操作要么完整生效，要么回滚，确保 Agent 与人类操作共享可靠撤销语义。

## 实现基线

机器可读的文档协议、runtime 协议和低层渲染后端版本记录在 `../engine-baseline.json`。更新协议或固定依赖必须作为独立、可审查的变更，并运行契约、序列化、撤销和视觉回归测试。

## 结果

### 正面结果

- 产品层和 Agent 获得稳定、可校验的设计语言。
- 引擎升级或替换被限制在适配器和兼容性测试内。
- MCP 可以安全暴露通用能力，而不是泄漏内部句柄。
- 预览、冲突和撤销成为所有写入者共享的行为。

### 代价与风险

- 适配器需要映射和序列化，可能增加延迟与维护成本。
- 最小公分母抽象会掩盖高级引擎特性，因此能力协商必须允许受控扩展。
- 公共契约和引擎状态可能暂时不一致，需要明确事件顺序和恢复机制。
- 视觉一致性无法只靠结构 contract tests 保证，仍需固定样例和渲染回归。

## 验证

- 为每个契约版本维护引擎无关 fixtures 和适配器 contract tests。
- 覆盖空文档、大文档、未知节点、缺失字体、损坏资源、版本冲突和取消。
- 同一事务在预演与应用时应产生一致的归一化差异。
- 固定基线升级前后比较关键样例的结构快照与渲染结果。

## 复审条件

当公共契约持续阻碍已验证的产品能力，或引擎的执行模型无法提供原子事务与稳定 ID 时，应复审契约粒度。复审优先扩展能力协商，不允许调用方临时绕过适配器。
