# ADR-0304：由模型选择设计操作，而不是宿主预判任务模式

- 状态：Accepted
- 日期：2026-09-06
- 关联：ADR-0302、ADR-0303、ADR-0160、ADR-0297
- 本决策取代启动时根据用户消息选择 `new-design/general` 与 `required/direct` 的实现，不改变文档事务协议。

## 决策

用户的最新消息、Conversation 历史、附件和当前文档共同构成模型上下文。宿主不通过关键词、正则、空页、选区或附件类型猜测这是新建还是继续修改，也不额外调用模型做意图分类。

### 单一请求与提示词

删除 `deliveryScopeReview` 请求字段、Main 双 setter 同步、Runtime 的初始模式 resolver 和两套 system prompt 分支。新请求契约拒绝旧字段；开发期不保留旧模式兼容路径。所有请求使用同一静态设计提示词与已有 planning 方法，用户文字只进入原有对话上下文。

### 中性工具入口

创建首切片、声明交付范围、执行计划、图片和 Page 操作等基础入口不再按自然语言意图隐藏。有真实文档 inspection 时，普通编辑入口直接可见，不要求重复检查以解锁。模型可在正常调用中选择适当操作，不需先调用模式选择工具。

专业工具仍使用原有阶段披露。阶段只能来自可信 inspection 和已成功工具调用，普通写入不冒充专业能力发现。模型可请求现有 capability discovery；本 ADR 实施时仍是成功发现后展开现有目录；该行为后续由 ADR-0307 的显式定向披露取代。

### 执行与完成

- 没有声明新交付时，普通对话、已有内容编辑和 Page 生命周期不受创作 scope 门禁阻塞。
- 模型通过 scope 工具登记交付后，Main 继续拥有稳定目标、画板预留位置、滚动步骤、提交 revision 与审核事实。不得用消息文本代替完成状态。
- 完成检查依据真实 scope、Plan、交付 ledger 和未解决写入失败，而不是起始请求中的意图开关。有未完成步骤仍不能宣称完成。
- 自动续跑的完成检查读取初始预检中的未完成 ledger，不把“本轮还没调用工具”当作完成。Page clear 仅使此前交付过期，后续新 scope、Plan 或失败仍正常检查。
- Scope 登记是设计工作流操作而非画布材料写入。登记失败仍报告错误并受重复失败抑制，但不制造必须提交新 revision 才能解除的恢复义务，也不能清除已有真实写入失败。
- 自动续跑由真实未完成 delivery 或剩余 stage 触发，不要求起始 Run 被宿主认定为“需要 scope”。原有取消、错误、次数边界不变。
- 不额外给 first-slice 增加缺 scope 硬门禁；未声明 scope 时原有单目标原子写入仍可执行。完整交付是否正确理解是模型任务，不用另一套宿主关键词校验模拟理解。

## 保留边界

工具可见不等于授权。Main 仍校验 Run、Design File、目标范围、能力与审批、revision；Renderer 与唯一 EditorRuntime 仍负责文档 invariant、引用、事务原子性和撤销。Page 跨页权限、外部资产授权不因中性入口而扩大。

已登记 scope 的重复/late 操作错误仍按真实执行状态返回。已有 Plan 对普通编辑的目标约束，以及 parser 异常的精细分类不在本次移除范围内，不能据此宣称所有历史编辑限制都已解决。

## 验证

- 不同语言和措辞、空页/有内容、选区/附件不改变同一真实检查状态下的基础工具集合。
- Provider 边界覆盖完整创建、编辑及多轮上下文请求，不增加意图分类回合。
- Main 回归覆盖 Page 操作不再要求创作 scope、已声明多目标仍续跑、取消和错误不续跑、已记录范围仍受保护。
- 完成检查保留未完成 ledger、参数错误及真实 revision 的约束；没有实际创作操作的消息允许正常回复。

代价是中性首轮比旧 scope-only 或只创建入口更大，但没有新增网络往返。使用真实 Runtime 上下文预算验证，不通过扩大生产预算绕过问题。自动化通过不等于真实生成审美和耗时已经验收。
