# ADR-0315：设计生成按真实 revision 渐进交付

- 状态：Accepted
- 日期：2026-09-07
- 关联：ADR-0080、ADR-0125、ADR-0230、ADR-0266、ADR-0297、ADR-0302

## 问题

生产生成链曾把公开 Plan、首切片、材料写入和后续编辑拆成多套模型工具与重复契约。模型既要规划宿主状态，又要一次提交人为 stage；任一字段漂移都会在画布产生内容前失败。生成工具成功后，Main 又立即把实现步骤标为完成并切到审核步骤，使同一目标的后续普通编辑可能被计划顺序拒绝。这既不是正常连续编辑，也无法做到一边生成、一边在画布显示真实结果。

## 决策

公开工具面只保留 `opendesign_generate_design` 作为新目标的起始材料写入。单目标直接生成；只有用户真实要求多个独立画板时才先声明一次 Delivery Scope。模型不提交独立 Plan，也不提交 stage、步骤状态、Page、Frame 身份、skill refs、brief fidelity 或其他 Main 已知事实。

一次生成调用提交一个完整、可见、可撤销的设计批次。Main 在同一原子事务中创建所需画板和该批内容，成功后立刻形成并渲染真实 revision；大型目标随后通过普通 `opendesign_edit_design` 调用继续追加批次。每个批次必须在视觉上形成有用边界，但不要求等待整套设计全部序列化后才首次写入。

Main 的执行账本仍是用户可见 Plan 的唯一事实源。实现步骤在连续材料写入期间保持 `in_progress`，材料 revision 本身不冒充步骤完成；模型主动调用 capture 表示当前实现批次已交付审核，Main 才以该精确 revision 完成实现步骤并激活 review/refine。布局或必需图片仍不满足时，capture 返回明确恢复动作并保持实现步骤未完成。审核通过后才完成 review/refine 与目标交付。

结构校验继续由同一 `DesignGenerationContract` 产生 Provider Schema、Main 解析和字段错误。Main 只注入可信宿主事实；相同无效输入指纹第二次出现时终止当前 Run，避免无画布进展的循环，但不污染下一条 Conversation 消息。Provider 首响应超时只允许在尚未发布任何语义内容时进行一次有界重试；已显示文本、reasoning 或工具内容后不重放。

## 结果

- 画布按真实 revision 渐进更新，而不是等待完整设计结束后一次渲染。
- 后续普通编辑可以在同一实现步骤中连续执行，直到 capture 明确进入审核。
- 用户可见 Plan 继续代表真实执行，不再由单次写入或模型说明提前变绿。
- 删除公开 Plan 与首切片产品概念，减少模型参数面、重复契约和无画布失败点。
- 单个工具调用仍保持原子性，取消或失败不会留下半棵非法层级；已经提交的较早 revision 保留并可撤销。

## 验证与限制

自动化覆盖生成工具单一解析、画板与材料原子写入、连续材料写入保持实现步骤活动、capture 后切换审核、同指纹失败有界停止、连续 Conversation 与历史附件保留、首响应超时重试和完整 Provider 工具披露。

这些测试证明执行与失败语义，不替代真实模型样张的耗时和视觉盲评。设计质量仍必须用打包产品记录首个材料 revision、连续批次间隔、契约失败率、最终完成率与样张质量。
