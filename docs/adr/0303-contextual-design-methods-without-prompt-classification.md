# ADR-0303：设计方法不再由最新消息关键词分类

- 状态：Accepted
- 日期：2026-09-06
- 关联：ADR-0098、ADR-0104、ADR-0243、ADR-0295
- 本决策取代按最新用户消息推断设计 Skill bundle 和画布语言的装配方式；不改变文档、Plan 或工具输入契约。

## 问题

Conversation 历史正常发送，但系统提示词另外仅根据 `request.prompt` 的关键词选择设计方法。用户从 Logo brief 进入“继续”或“改一下”时，历史还在，Logo Skill 却可能消失。中英文字符统计还可能用新的宿主语言指令覆盖此前明确的画布文案要求。

恢复历史关键词回溯、增加分类模型调用或持久化第二套意图状态，仍然是在宿主替模型判断需求，不能从根本上解决职责混淆。

## 决策

- 普通与首切片提示词均提供现有 planning 方法及其适用领域，由模型结合完整对话、当前设计与用户要求应用相关方法。不把 UI 专属规则强制用于 Logo、海报等图形任务。
- 不根据最新消息的文字选择、撤下或切换 Skill；不预先用字数/正则指定画布语言。模型延续用户已经要求的内容语言，并尊重后续修改。对话回复语言与画布文字语言可以不同。
- 不追加分类 Provider 调用、不新增工具、不复制历史到系统提示词，也不修改 Conversation 原始消息。现有上下文预算继续覆盖最终 system、tool schema 与历史。
- Plan 中的 `deliverable` 仍由模型声明，Main 依该结构字段绑定内部 skill refs；独立 Critic 仍按声明的交付类型加载审核方法。该绑定不是对用户文本做意图分类。
- 本 ADR 只处理设计方法与语言装配；工具可见阶段与 `deliveryScopeReview` 关键词路由的后续移除见 ADR-0304。

## 验证与代价

- Provider 边界回归连续发送 Logo brief、“继续”、新 UI 要求：每条消息只触发正常模型请求，原文与历史保留，planning 方法不会随最新消息消失。
- 保持用户所选 reasoning effort，不强制低思考；不把 Critic bundle 注入作者上下文。
- 固定 planning 上下文比只注入某一类型方法更长，但没有额外网络往返。验证使用实际 Runtime 的模型上下文预算和请求成功路径，不调整生产限制来迁就测试，也不维护另一套固定字符门槛。
- Mock Provider 测试证明装配和连续对话行为，不证明真实模型已达到视觉质量标准；真实生成耗时与审美仍需评测。
