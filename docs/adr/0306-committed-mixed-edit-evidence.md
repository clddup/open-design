# ADR-0306：混合编辑按已提交变更记账

- 状态：Accepted
- 日期：2026-09-06
- 关联：ADR-0302、ADR-0304、ADR-0305

## 问题

统一 Edit Design 虽然支持 node、hierarchy、arrange 组合，但只要 Plan 提供潜在 rebase 信息，混合批次就被拒绝，即使当前 revision 没有冲突。原 Main handler 又根据输入预估目标和新节点：存在 node entry 时可能漏记其他 entry 的目标，将同批次所有新分组添到错误的画板。

## 决策

- 混合批次以精确 revision 执行，不再因潜在 rebase 信息直接拒绝。只有独立的纯插入批次保留原有受控 rebase；发给 Renderer 的输入和 Main 的结果校验使用同一收窄后的授权。
- 复用唯一 EditorRuntime 已返回的 `DesignChangeSet`，不要求模型回抄证据，也不增加工具或模型往返。Main 使用原权威 Schema 解析，并将 documentId、fromRevision、toRevision 与实际返回的 designRevision 对齐。成功写入缺少或错配结果证据属于内部错误，保留已提交内容，不重放编辑。
- 由真实 before/after 父链计算每个 Plan 画板的物理后代和受影响状态。分组属于哪个画板由提交后的结构决定；包住 Plan 根的分组是祖先，不冒充每个画板的后代。
- 直接改变物理成员与共享定义/祖先间接影响分开：两者可以使审核证据失效，但只有授权目标上的真实直接变更进入原来的步骤记录。不存在真实变更时不以工具成功或新 revision 冒充材料进度。
- 删除 handler 基于输入汇总所有目标和全局 createdNodeIds 的记账分支，统一在成功事务后协调。现有 Renderer 页面授权、事务原子性、严格 stale revision 和 undo 不变。

## 只读缓存

首切片与后续 Edit Design 共用提交证据入口。变更集基线与原 inspection 精确匹配时，在原缓存中推进层级投影；节点投影复用原 inspection parser 的同一函数，不创建第二份 DesignDocument。基线不匹配时不声称缓存已更新，影响查询不使用过期父链猜新成员；不完整链只应用已证明的成员增删，不能用不完整投影覆盖已经依据已授权 node 事务登记的新成员，也不凭空为其他目标分配新节点。

## 验证与边界

- Main→Renderer→EditorRuntime：属性修改 A + 分组 B，一次提交、一次 undo，两个目标均记录真实修改，分组不串到 A，B 的未执行步骤不被完成。
- 查询覆盖独立分组、包裹根节点、跨父级移动、删除、共享组件/资源、无变化与不完整层级。
- 只读缓存覆盖连续移动与后续编辑、Page roots、组件删除、namespace 和原对象不变；不匹配基线不推进缓存。真实首切片→深层插入→再次修改新节点的串联回归同时覆盖精确缓存和其他写入造成的缓存缺口。
- 本次是混合提交与证据修复，不代表节点编辑已解除全部 Plan 范围限制；跨计划删除、完整通用编辑授权与专业工具定向披露仍需继续推进。真实模型视觉质量不由这些测试证明。
