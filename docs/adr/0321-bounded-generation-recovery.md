# ADR-0321：保留用户需求并限制无进展的生成恢复

- 状态：Accepted
- 日期：2026-10-14
- 关联：ADR-0316、ADR-0317、ADR-0318

## 目的

避免模型在丢失需求、不可见参数限制或重复审核中长时间返工。错误不提交，已有成果保留；回复结束、审核结果与设计执行事实继续分别建模。

## 决策

1. 模型可见参数与 Main 结构校验共用 Contract。能由 Schema 表达的 `kind` 分支字段限制只在 Schema 中定义，不留在模型不可见的重复结构 refinement 中。错误类型、范围及有界实际值来自同一 Schema。生成使用 call-local ID，普通编辑使用 Main 签发的新实体 namespace，提示词不混淆两者。
2. Context checkpoint 只压缩执行过程，不以每条前 600 字或最近 12 条替代用户需求。完整原始用户消息及授权附件引用按来源顺序恢复；旧 checkpoint 同样从仍保留的 journal 恢复。Run 内压缩也保留用户消息。确实超出模型窗口时显式返回 context 错误，不静默删掉需求，不额外调用分类或摘要模型。
3. 失败输入的实际值属于诊断，不属于稳定错误根因。工具、规则与字段身份用于重复失败计数；独立字段或规则不合并为同一个循环。正确写入后的恢复沿用既有 revision 语义。
4. Main 在 Run 生命周期内复用相同审核证据的结果。证据身份包括准确目标、revision、内容寻址截图、原始需求、参考与质量条件及审核模型；证据变化或新用户 Run 不复用旧结果。缓存不是 verified 事实，审核后仍重新检查当前 revision。重复相同证据或同一目标多次审核无改善时有界停止自动审核，保留真实发现并明确报告限制；不能把服务故障说成设计缺陷，也不能因此阻止普通编辑、其他目标或正常回复。
5. `budget` 不自动证明值得继续。自动续跑必须有本 Run 的真实材料 revision 或新增验证证据；继承的账本、读取、重复 capture 与消息文本不是进展。没有进展时使用既有 needs-attention 路径；最多三次续跑、取消优先和正常结束不重启保持不变。

## 兼容与安全边界

不改变 DesignDocument、DesignTransaction、持久 Conversation/journal 或 capability 模型。Group 的结构限制原本已在 Main 拒绝，只将同一限制提前披露。旧 checkpoint 不重写，也不删除原始历史。审核缓存与进展计数是 Main 的可丢弃 Run 状态，不保存模型凭据，不引入第二份设计事实。

如果实现引入新的 workflow failure enum，同步 Agent 协议小版本与 engine baseline；新错误不作为旧版本可执行消息降级重放，历史 journal 保持可读。

本轮新增 `visual_review_no_progress`，Agent 协议升级为 `3.14.0`。Main 的可丢弃审核控制器按 Run、文档与目标计数：相同证据可复用一次；连续三次失败审核未超过历史最好 criterion score，或同一目标已完成六次独立审核后，后续自动审核返回稳定错误与恢复动作。有效改善重新开始无改善计数，但不取消总次数上限。Provider 异常与取消不记为设计失败，也不缓存其结果。普通编辑、其他目标与下一条用户消息不受审核计数限制。

UI 将该错误明确显示为审核暂停，不折叠成“正在修正设计”，也不标为通过。缓存只复用独立 Critic 的意见；每次使用后仍执行当前文档 revision 检查与原有 Main ledger 处理。

## 验证边界

原始用户附件属于需求事实；工具返回的旧截图与本地执行 checkpoint 属于可压缩的执行投影。Runtime 用局部对象来源标记区分，并在 Pi 往返中保留标记；不增加 wire 字段，不根据用户文本、文件名或自然语言关键词猜测来源。压缩旧工具截图不删除 journal、授权附件或当前可读文档事实。

回归必须覆盖长需求尾部约束、超过 12 条用户消息、旧 checkpoint 恢复、同根因错误值变化、独立错误、精确审核证据变化、无改善限制、取消、普通编辑与下一 Run，以及无进展预算续跑。

本轮自动化证明执行与恢复语义，不证明真实 LLM 永远符合需求，也不替代真实模型视觉质量或 macOS/Windows 原生产品验收。实际命令与结果在交付时列出；不引入新的 package 脚本、UI 组件库或通信协议迁移。
