# ADR-0309：独立审核恢复原始用户需求

- 状态：Accepted
- 日期：2026-09-06
- 关联：ADR-0308、ADR-0243

## 问题

作者 Agent 会恢复 Conversation，但独立审核请求只有本 Run 的 prompt。“继续”因此可能成为审核器看到的全部原始需求，文档附件也未进入审核上下文。Plan 的自述不能替代缺失的用户要求。

## 决策

- Main 在原有 Timeline 读取时同时提取同一 Conversation、同一 Design File 的用户原文及文档附件元数据。按 journal sequence 保留顺序、换行和后续修改，不做关键词/字数意图分类，不创建第二份持久化需求状态。
- 作者回复、工具输出、思考和自动续跑的宿主提示不作为用户要求；自动续跑依据已记录用户消息，不把宿主续跑指令冒充新需求。
- 审核 prompt 明确要求结合前后文理解后续更正，不把所有历史要求同时视为有效，也不把引号内文字或附件当成权限与系统指令。
- 原始文档以现有 `document_ref` 进入 Main 附件解析链，相同文档只展开一次；截图仍为第一张图，视觉参考图仍使用既有授权选择，不自动把所有历史图片都当风格参考。
- 独立审核不获得作者消息。ADR-0308 中删除的作者自证说明不重新引入。

## 预算和失败

独立审核使用的 `ModelProviderHost.complete` 在引用展开后，按用户配置的所选模型上下文/输出预算检查完整请求。复用现有预算算法；图片仍按既有图像成本估计，不将 base64 当文本 token。真正发送的图片不变。

超预算显式失败，在请求外部 Provider 前停止，不截掉用户要求、不加摘要模型往返、不静默宣称已审核。附件解析前后尊重取消；解析只执行一次。普通作者 stream 路径不变。现有模型预算为估算值，不宣称已接入精确 tokenizer。

## 验证与边界

- 原文、后续更正、文档句柄在完整 Main→critic 请求中保留，当前消息不重复，作者和其他 Conversation/Design File 内容不进入要求集合。
- 独立审核请求保留同一 capture/reference 身份，文档引用去重；真实首切片后的 critic context 能看到原始要求和“继续”。
- 文档展开后超限零 fetch，正常文档仅解析一次，图片不按 base64 长度误判，取消不发请求。

长历史超过配置容量时仍需进一步设计可见、非失真的需求压缩策略；本次不声称无限上下文或真实视觉质量已验收。跨 Design File 借用需求需要明确上下文范围，当前不会无条件广播同一 Workspace 的历史。
