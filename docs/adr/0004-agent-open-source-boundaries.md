# ADR-0004：Agent、MCP 与 skills 的开放源码边界

- 状态：已接受
- 日期：2026-08-07

## 背景

OpenDesign 希望借鉴 Pi/OpenCode 等开放 Agent 项目的成熟思路，并允许社区通过 provider、MCP 和 skills 扩展设计工作流。相关项目的代码许可证、商标、依赖和安全假设并不天然一致；扩展内容还可能携带提示注入、恶意脚本或过宽权限请求。

“开源可见”不等于“可以直接复制”，安装 skill 也不等于用户同意执行其中任何动作。项目需要同时保护许可证合规、核心产品独立性和用户设计数据。

## 决策

### 架构参考与代码复用分离

团队可以参考公开项目的概念、交互和架构模式，例如小型 Agent 循环、事件化会话、工具注册、provider adapter 和可组合扩展。任何源代码、测试、提示词、协议文本或资源的复制与改写都必须在合入前记录来源、固定修订、许可证、版权声明和修改情况。

无法确认许可证兼容性时，只能独立实现公开思想，不复制表达或代码。项目名称和界面不得暗示与 Pi、OpenCode 或其他参考项目存在官方关联。

ADR-0020 完成了首个 Pi 代码复用审查：OpenDesign 固定 MIT License 的 `@earendil-works/pi-agent-core 0.84.1`，只通过自有 adapter 迁移已实现的 headless `Agent`。固定版本的 `AgentHarness` contract test 证明其 `prompt()` 尚未实现，因此拒绝接入；`@earendil-works/pi-coding-agent` 和 `@earendil-works/pi-tui` 也保持禁止。该裁决不会把 Pi 的文件、shell、凭据、资源发现或 session 权限带入 OpenDesign。

### 核心与扩展边界

开放的稳定边界包括版本化 Agent 消息、工具 schema、Design Contracts、MCP 标准接口和 skill 清单格式。Electron 特权 API、凭据存储、原始引擎句柄、内部遥测和未公开文件格式不属于扩展 API。

扩展只能请求已命名的能力。主机根据来源、签名或完整性、工作区策略、当前文档和用户同意授予临时或持久权限；扩展自身不能声明已获授权。

### MCP 双向策略

OpenDesign 作为 MCP 客户端时，外部 Server 返回的工具描述、资源和文本均视为不可信数据。OpenDesign 作为 MCP Server 时，只向已认证且获准的 Client 暴露稳定工具，并对读取、导出和写入分别授权。

两个方向都通过 Tool Runtime 执行 schema 校验、超时、速率与大小限制、风险分级、同意、审计和撤销。MCP transport 的连接成功不等于工具调用获得批准。

### Skills 策略

Skill 的说明文本可以影响 Agent 的工作方法，但不能覆盖系统策略、项目规则或用户授权。Skill 中的脚本、二进制、网络引用和动态依赖在执行前需要独立许可与限制。

安装时记录来源 URL 或发布者、版本/提交、内容哈希、许可证和请求能力。执行时固定解析后的版本，避免会话中途远程内容变化。更新后的 skill 重新评估权限，新增能力不能继承旧同意。

默认禁止以下行为：

- 读取项目、用户选择范围或显式输入之外的文件。
- 访问系统密钥链、环境密钥、浏览器数据或其他应用数据。
- 未经批准执行 shell、下载程序、安装依赖或访问网络。
- 将设计内容、提示词、工具结果或身份信息发送到未声明端点。
- 把文档文本、网页、MCP 输出或工具错误中的指令当成高优先级策略。

### 许可与发布

直接 vendored 组件记录在 `THIRD_PARTY_NOTICES.md` 和 `docs/engine-baseline.json`。JavaScript、Rust 和打包产物的完整依赖清单应在发布流水线中从锁文件生成，并随分发物保留所需许可证文本。

升级、替换或新增依赖时，评审其许可证、通知、源代码提供义务、专利条款、商标和模型/数据使用限制。不得仅凭依赖名称或仓库可公开访问推断其许可证。

## 结果

### 正面结果

- OpenDesign 可以吸收开放生态的经验，同时保留可证明的独立实现边界。
- MCP 与 skills 共享一致权限模型，减少隐式信任路径。
- 用户能够理解扩展的来源、数据访问和副作用。
- 固定版本与通知文件提高构建可复现性和发布合规性。

### 代价与风险

- 扩展安装与首次执行需要更多提示和策略管理。
- 独立实现可能比直接移植耗时。
- 许可证和来源数据需要持续维护，自动生成结果仍需人工审查。
- `utilityProcess` 和脚本限制不能替代真正的 OS 沙箱；高风险能力仍应默认关闭。

## 验证

- 对恶意 skill、提示注入、路径穿越、命令拼接、超大 MCP 响应和权限升级编写负面测试。
- 验证断开 Client/Server、撤销授权和切换工作区后，旧能力立即失效。
- 发布检查应比对锁文件、vendored 提交、许可证扫描结果和第三方声明。
- 代码评审中对参考实现的相似代码要求明确 provenance 记录。

## 复审条件

当扩展需要新的高权限能力、项目开始分发第三方 Agent 代码、采用远程 skill 市场，或许可证/安全模型发生变化时，应新增 ADR 取代或补充本决策。
